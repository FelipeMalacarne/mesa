# ADR 0004: DBML is the text form of the schema model

Status: accepted · 2026-10-21

## Decision

The schema designer edits a database as a diagram and as DBML text, both bound to `core/schema`. Mesa ships its own parser and printer (`internal/dbml`), engine-neutral, round-tripping with the public DBML syntax (tables, columns, settings, refs, enums, indexes, notes, `Project`).

## Reasons

- Open, widely used and readable; diffs well in Git.
- Not tied to PostgreSQL, so the same model serves other engines.
- A custom language would cost a parser and lose compatibility with other tools.

## Consequences

- Diagram positions are never stored in DBML (they go to `store.Layouts` or `*.layout.json`).
- Engine-specific types are kept verbatim as type names; the dialect validates them at plan time.
